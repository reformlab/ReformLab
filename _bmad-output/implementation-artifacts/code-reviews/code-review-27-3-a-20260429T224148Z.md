## 🐍 Pythonic Crimes & Readability

- **Redundant ARIA role:** `role="button"` is explicitly set on native `<button>` elements at lines 375 and 403. Native `<button>` has implicit `role="button"`. The story spec even acknowledged this: "with `role='button'` (implicit)" — meaning *don't add it explicitly*. This is ARIA 1.1 anti-pattern noise.
  - 📍 `PortfolioCompositionPanel.tsx:375, 403`

- **`aria-expanded` is vacuously always `false`:** Group chips are only rendered inside `{!isExpanded && ...}`. Therefore `aria-expanded={isExpanded}` on every chip is always `false` at render time — the attribute communicates nothing. The card expand button (line 495) already correctly carries `aria-expanded`. The chip's attribute is dead weight but could mislead screen-reader users into thinking this button is itself an expandable control.
  - 📍 `PortfolioCompositionPanel.tsx:378, 406`

## ⚡ Performance & Scalability

- **[MEDIUM] O(n) double schema lookup per parameter in `summarizeParameterGroup`:** For each `paramId` in a group, the function calls `schemas.find((s) => s.id === paramId)` **twice**: once as the third argument to `resolveParameterValue()` (line 146) and again immediately after as `const schema = schemas.find((s) => s.id === paramId)` (line 147). For a template with 20 schemas and a group with 10 parameters, this is 200 redundant iterations per render per card. A simple `const schema = schemas.find((s) => s.id === paramId)` hoisted before both calls eliminates this entirely.
  - 📍 `PortfolioCompositionPanel.tsx:146-147`
  - 💡 Fix: Hoist the `schemas.find` call, pass the result to both `resolveParameterValue` and the `formatParameterValue` call.

## 🐛 Correctness & Safety

- **🐛 Bug: Nested `setTimeout` leaks on unmount:** `handleGroupChipClick` (line 233) creates a `setTimeout(() => { ...; setTimeout(() => setHighlightedGroupId(null), 1000); }, 0)`. If the component unmounts while the 1000ms inner timer is pending — e.g., the user navigates away immediately after clicking a chip — React fires a state update on an unmounted component. No cleanup ref or `useEffect` return fn exists. The story notes mention fake timers but not cleanup.
  - 📍 `PortfolioCompositionPanel.tsx:242-249`
  - 🔄 Reproduction: Click a group chip, immediately navigate to a different stage (triggering unmount), wait 1000ms — React warning fires in dev mode: *"Can't perform a React state update on an unmounted component"*.

- **🐛 Bug: `summarizeRateSchedule` hardcodes `"€/tonne"` fallback:** Line 182 defaults to `"€/tonne"` when no schema with `rate_schedule` or `rate` in its ID is found. This is wrong for every non-carbon-tax policy type (vehicle malus shows `"50 €/tonne in 2025"` instead of `"50 €"` or `"50 pts"`). Worse, the match predicate `p.id.includes("rate")` is dangerously broad — `income_rate`, `poverty_rate`, `malus_rate_per_gkm` all match, potentially returning the wrong schema's unit entirely.
  - 📍 `PortfolioCompositionPanel.tsx:181-182`
  - 🔄 Reproduction: Add a `vehicle_malus` or `energy_poverty_aid` policy with a rate schedule to the composition. The schedule chip will display `"50 €/tonne in 2025"` regardless of the actual policy unit.
