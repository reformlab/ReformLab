### 🐛 Bug 1: AC-8 URL hash migration is silently broken

- 📍 `frontend/src/contexts/AppContext.tsx:221-232`
- 🔄 Reproduction:
  1. User has bookmark or localStorage-restored URL `#population/population-explorer`
  2. App loads and fires `onHashChange()`
  3. `hash = "population/population-explorer"`, `sub = "population-explorer"`
  4. `isValidSubView("population-explorer")` returns **true** (it's in `VALID_SUBVIEWS` set, `workspace.ts:132`)
  5. Code enters the first `if (sub && isValidSubView(sub))` branch and sets `subView = "population-explorer"` — **the migration else-branch is never reached**
  6. `window.location.hash` is never rewritten; it stays as `#population/population-explorer`
  7. On next reload the same legacy URL is processed identically — migration never happens

  The migration code at the else-if branch (`else if (stage === "population" && sub)`) is dead for `"population-explorer"` because it's pre-empted by `isValidSubView()` returning true. The fix is to check the migration map **before** the validity check, or remove `"population-explorer"` from `VALID_SUBVIEWS`.

  The app still *works* because `PopulationStageScreen` handles `activeSubView === "population-explorer"` as a fallback, but AC-8 explicitly states "legacy hashes like `#population/population-explorer` are migrated on app load." They are not.
