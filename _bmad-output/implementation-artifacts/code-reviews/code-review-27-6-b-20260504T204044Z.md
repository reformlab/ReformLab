## 🏛️ Architectural Sins

- **[8/10] Single Responsibility + Open/Closed:** `getStageStatus` mixes "is data present" (read from multiple props) with "did user touch it" (read from `stageTouched`). These are two orthogonal concerns. Worse, the engine case embeds the rule `dataSatisfied = investmentDecisionsEnabled !== null || isTouched` — `isTouched` already appears in the outer gate (`dataSatisfied && isTouched`), creating a double-count. If `isTouched` alone makes `dataSatisfied = true` for engine, then mere stage visits (once `stageTouched.engine` is wired up) would immediately flip the stage green without an explicit decision.
  - 📍 `frontend/src/components/layout/WorkflowNavRail.tsx:88-96`
  - 💡 Fix: `dataSatisfied` for engine should be `investmentDecisionsEnabled !== null` only; the `isTouched` guard belongs exclusively in the outer `dataSatisfied && isTouched` check.

- **Backward-compatibility debt as permanent architecture:** The `hasStageTouched` flag creates two code paths that will co-exist forever because `createNewScenario` never writes `stageTouched`. The "new path" is unreachable for real user scenarios today. Leaving the legacy path active until all construction sites are fixed means the fix cannot be trusted.
  - 📍 `frontend/src/contexts/AppContext.tsx:563-600`, `frontend/src/components/layout/WorkflowNavRail.tsx:102-114`
