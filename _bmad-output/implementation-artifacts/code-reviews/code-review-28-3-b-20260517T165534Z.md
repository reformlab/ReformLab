## 🏛️ Architectural Sins

### OCP Violation — `_build_decision_columns` dual return type

**[7/10] Open/Closed:** `_build_decision_columns()` now returns `tuple[pa.Table, dict[str, list[str]]] | pa.Table` — its return type varies depending on whether `decision_log` is non-empty. The caller must do `isinstance(build_result, tuple)` to dispatch, which is a classic OCP smell. The function was extended by modifying its return contract rather than extending it cleanly.

- 📍 `src/reformlab/orchestrator/panel.py:234` (signature), `panel.py:121-139` (dispatch)
- 💡 Fix: Always return `tuple[pa.Table, dict[str, list[str]]]` — return an empty dict `{}` when `decision_log` is empty. This removes the `isinstance` dispatch entirely and keeps callers simple.

## 🐍 Pythonic Crimes & Readability

- **`Any` parameter type on public function:** `capture_technology_set(technology_set: Any)` — the project rules mandate `TYPE_CHECKING` guards for cross-module type annotations. This function must accept a concrete type.
  - 📍 `src/reformlab/governance/capture.py:383`
  - Should be:
    ```python
    if TYPE_CHECKING:
        from reformlab.discrete_choice.technology_set import TechnologySet

    def capture_technology_set(technology_set: TechnologySet | None) -> dict[str, Any]:
    ```
  - The current `hasattr()` duck-typing approach accepts any arbitrary object with `.domains` and `.version`, silently serializing garbage.

  - 📍 `tests/discrete_choice/test_domain_utils_writeback.py:22-23`

  - 📍 `src/reformlab/governance/manifest.py:183`

- **Hardcoded incumbent column names:** Both StateUpdateSteps hardcode the string:

## 🐛 Correctness & Safety

### Bug 1: Integration test mutates frozen YearState

- 📍 `tests/discrete_choice/test_domain_utils_writeback.py:640,644`
- 🔄 Reproduction:

```python
# Line 634: state created as frozen YearState with data dict

    "population_data": population,
    "discrete_choice_result": vehicle_choice,
})
# Line 640: MUTATION of the frozen state's internal dict — works at runtime
# because frozen only prevents reassignment of the 'data' attribute itself,
# not mutation of the dict it references

...
# Line 644: mutating data dict of the returned (supposedly new) YearState
state_after_vehicle.data["discrete_choice_result"] = heating_choice  # ← same problem
```

The project contract requires `replace(state, data={**state.data, "key": value})`. The test pattern is not valid according to project conventions and sets a dangerous precedent. It also happens that `VehicleStateUpdateStep.execute()` does a shallow `dict(state.data)` copy, so this particular test passes correctly at runtime — but only by accident. The test does not prove what it claims to prove.

### Bug 2: `{domain}_to` panel column shows "keep_current" sentinel, not resolved technology

- 📍 `src/reformlab/discrete_choice/vehicle.py:467`, `heating.py` (equivalent)

```python
transition_record = TransitionRecord(
    ...
    to_alternative_ids=choice_result.chosen,  # raw: ["ev", "keep_current", ...]
)
```

`apply_choices_to_population()` correctly resolves "keep_current" → preserved incumbent in the population frame. But `TransitionRecord.to_alternative_ids` captures the raw choice BEFORE resolution. The panel column `{domain}_to` then contains "keep_current" for households that kept their existing technology, not the actual technology they retained.

AC-5 states: _"it includes `{domain}_from` and `{domain}_to` columns showing each household's **technology transition** per year."_ A row where `heating_from="gas_boiler"` and `heating_to="keep_current"` does not show a technology — it shows a choice code. Analysts cannot tell from the panel alone that the household ended the year with "gas_boiler".
