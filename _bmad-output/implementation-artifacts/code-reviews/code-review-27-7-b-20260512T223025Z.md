## 🐛 Correctness & Safety

**🐛 Bug: visitedSteps initialization creates stale state when config changes**
- 📍 `InvestmentDecisionsWizard.tsx:53-55`
- 🔄 Reproduction: 
  1. Mount wizard with `investmentDecisionsEnabled: false` → visitedSteps initialized as `Set([0])`
  2. Parent updates props to `investmentDecisionsEnabled: true` (same component instance)
  3. visitedSteps remains `Set([0])` but auto-advance effect marks step 1 as visited
  4. Result: Inconsistent state - initialization claimed step 1 was visited but it wasn't
- 💡 Fix: Initialize visitedSteps based solely on `activeStep`, not `isEnabled`:
```tsx
const [visitedSteps, setVisitedSteps] = useState<Set<WizardStep>>(new Set([0]));
```

**🐛 Bug: useEffect dependency exclusion creates subtle race condition**
- 📍 `InvestmentDecisionsWizard.tsx:74-85`
- 🔄 Reproduction:
  1. Component mounts with `isEnabled: true` and `activeStep: 1` (auto-advanced)
  2. User quickly clicks Next before first effect completes
  3. `activeStep` becomes 2, but effect still has closure with `activeStep === 1`
  4. Effect runs with `isEnabled: true` and `activeStep === 1` from stale closure
  5. Result: May incorrectly mark step 1 as visited again or execute wrong branch
- 💡 Fix: Include `activeStep` in dependencies and add guard:
```tsx
useEffect(() => {
  const stepRef = { current: activeStep }; // Capture current value
  // ... rest of effect
}, [isEnabled, activeStep]);
```

**🐛 Bug: auto-advance effect may overwrite visitedSteps unnecessarily**
- 📍 `InvestmentDecisionsWizard.tsx:76-78`
- 🔄 Reproduction:
  1. User manually navigates from step 0 to step 1 (not via auto-advance)
  2. `goToStep(1)` marks step 1 as visited
  3. User toggles enable/disable, then re-enables
  4. Effect runs and adds step 1 to visitedSteps again (redundant Set creation)
  5. Result: Unnecessary state updates and re-renders
- 💡 Fix: Check if step already visited before updating:
```tsx
setVisitedSteps((prev) => prev.has(1) ? prev : new Set([...prev, 1]));
```

**🐛 Missing Edge Case: Click to unvisited step not prevented**
- 📍 `InvestmentDecisionsWizard.tsx:174`
- 🔄 Reproduction:
  1. Start with wizard enabled (on step 1, visitedSteps = Set([0, 1]))
  2. Click step 2 (Parameters) button without ever visiting it
  3. `isClickable` is true because step 2 is in visitedSteps from initialization
  4. Result: User can jump to unvisited step, violating AC-2
- 💡 Fix: The initialization should not pre-mark steps as visited:
```tsx
const [visitedSteps, setVisitedSteps] = useState<Set<WizardStep>>(new Set([0]));
```
