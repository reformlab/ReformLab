## 🐛 Correctness & Safety

### 🎭 Issue 1 — Vacuous truth: null-check assertions on unguarded filtered sequences

**Lying test pattern.** Both tests 1 and 2 filter by year and then assert non-null / all-null on the result without first asserting the filtered row count.

```python
# test_panel.py:801-802 (also 864-865, 867-868)
year_2024_rows = panel.table.filter(pc.equal(panel.table.column("year"), 2024))
assert not any(v is None for v in year_2024_rows.column("heating_chosen").to_pylist())
```

`not any(v is None for v in [])` evaluates to `True` for an empty list. If the year column had a type mismatch (e.g., produced as `int32` vs the literal `2024` which is Python int), `pc.equal` could silently return zero matching rows. The assertion would pass, falsely claiming non-null values exist for year 2024.

**Fix:** Add `assert year_2024_rows.num_rows == n` before each null-check block.

---

### 🎭 Issue 2 — `heating_probabilities`, `heating_utilities`, `decision_domains` null-fill never asserted

Tests 1 and 2 only assert `"heating_chosen" in panel.table.column_names` and check that column's null pattern. They completely skip the other three columns that `_build_decision_columns` injects per domain:

| Column | Type | Null-fill risk |
|--------|------|---------------|
| `heating_probabilities` | `pa.list_(pa.float64())` | List-type null-fill is version-sensitive in PyArrow |
| `heating_utilities` | `pa.list_(pa.float64())` | Same |
| `decision_domains` | `pa.list_(pa.string())` | Same |

PyArrow's permissive promotion of list-typed columns into null slots behaves differently from scalar types (and has changed across minor versions). A PyArrow upgrade could silently break null-fill for list columns. These are the highest-risk columns and they have zero coverage in the new class.

The dev notes even call this out: *"Do not assert `pa.types.is_null(...)` for null-fill scenarios"* — which acknowledges the complexity but the response was to test *nothing* for these columns instead of testing the column's presence and using `pc.is_null()` with a count check.
