### Issue 2 — `role="button"` documented but not implemented (and shouldn't be)

**File:** `_bmad-output/planning-artifacts/ux-design-specification.md:1782`

The spec says: `role="button" on step label buttons`. The implementation in `InvestmentDecisionsWizard.tsx` correctly uses `<button>` elements without `role="button"`. Adding `role="button"` to a native `<button>` is redundant and is called out as an anti-pattern in WAI-ARIA Authoring Practices 1.2. The spec documents invalid/non-existent ARIA usage that would cause any accessibility review to flag a false positive.

### Issue 3 — Breadcrumb separator character and styling wrong

**File:** `_bmad-output/planning-artifacts/ux-design-specification.md:1912-1913`

**Separator:** Spec documents `Results > {sub-view name}` (chevron `>`), but the implementation renders:
```tsx
<span>Results</span>
<span className="text-slate-400">/</span>
<span className="font-medium text-slate-700">{subViewLabel}</span>
```
— a forward slash `/` separator.

**Styling:** Spec says "Lightweight styling: `text-sm text-slate-500`", implying the breadcrumb is muted. But the sub-view name uses `font-medium text-slate-700` — meaning it's **bold and dark**, not lightweight. The outer `div` has `text-slate-500`, but that's the "Results" label, not the sub-view name. The spec implies uniformly muted styling when the actual design deliberately emphasizes the current sub-view name.
