## 🐛 Correctness & Safety

**🐛 Bug: `handleToggle` bypasses `goToStep()`, permanently orphaning step 1 from `visitedSteps`**

- 📍 `InvestmentDecisionsWizard.tsx:128-130`
- 🔄 Reproduction:
  1. Render wizard with `investmentDecisionsEnabled: false`
  2. Click the toggle → `handleToggle(true)` runs → `setActiveStep(1)` is called directly (not via `goToStep`)
  3. React batches state: `activeStep` becomes `1`
  4. Parent re-renders with `isEnabled = true`; `useEffect([isEnabled])` fires
  5. Inside useEffect: `isEnabled && activeStep === 0` → `true && false` = **false** — `setVisitedSteps` is never called
  6. `visitedSteps = {0}` (step 1 absent)
  7. User clicks Next through steps 2 and 3: `handleNext` adds `{2}` then `{3}`, but step 1 is never added
  8. On Review step (step 3), click the "Model" breadcrumb button: `isVisited = false` → `isClickable = false` → `isClickable && goToStep(1)` = noop. **AC-1 and AC-3 broken.**
  - The existing tests never hit this path: all six new tests start with `investmentDecisionsEnabled: true` in initial props, which seeds `visitedSteps = new Set([0, 1])` via the `useState` initializer, bypassing `handleToggle` entirely.

**🐛 Bug: Current active step renders as green "completed" instead of blue "current" for steps 1-3**

- 📍 `InvestmentDecisionsWizard.tsx:164`
- 🔄 Reproduction:

## 🐍 Pythonic Crimes & Readability

**Accessibility: `disabled` removes breadcrumb from tab order (AC-5 keyboard violation)**

- 📍 `InvestmentDecisionsWizard.tsx:175`
- AC-5 requires "keyboard-focusable behavior." The HTML `disabled` attribute removes an element from the tab order entirely. Screen reader users navigating by Tab cannot discover or hear the names of unreached steps. The WAI-ARIA authoring practices for breadcrumb/step navigation specify using `aria-disabled="true"` **without** the `disabled` attribute so the element remains focusable (Tab reaches it) but announces as disabled. The current code sets both, which removes it from tab order.

**`aria-disabled={isDisabled}` emits `aria-disabled="false"` on enabled buttons**

- 📍 `InvestmentDecisionsWizard.tsx:178`
- WAI-ARIA 1.2 §6.6.3: "Authors SHOULD NOT use aria-disabled if the element can be made enabled." More practically: setting `aria-disabled="false"` is redundant and some screen readers announce it explicitly ("not disabled"), creating noise. Omit the attribute entirely when `isDisabled` is false.
