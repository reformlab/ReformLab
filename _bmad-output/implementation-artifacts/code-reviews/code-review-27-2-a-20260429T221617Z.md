### Issue 3 — `var(--color-white)` vs. `#ffffff` — inconsistency introduces silent fragility

📍 `_bmad-output/branding/theme.css:52`

All other opaque-white surfaces in the same file use the literal hex value:
```css
--color-surface-primary: #ffffff;   /* literal — explicit, stable */
```

The new tokens use an internal Tailwind reference:
```css
--color-popover: var(--color-white);  /* implicit — depends on Tailwind internals */
```

`--color-white` is defined at `node_modules/tailwindcss/theme.css:323` — a private file in Tailwind's package. Tailwind v4 does define it (`#fff`), so it works today. But:

1. It is undocumented in Tailwind's public API (not in the changelog or upgrade guide as a stable token).
2. If Tailwind renames or removes `--color-white` in a minor release, the popover background silently becomes transparent again — the exact bug this story was meant to fix permanently.
3. It creates a pattern inconsistency that future developers may copy, spreading the fragility.

The fix is one character: `#ffffff` instead of `var(--color-white)`. This is how `--color-surface-primary` is already written.

### Issue 5 — Test does not verify the CSS actually resolves to a non-transparent colour

📍 `PoliciesStageScreen.categories.test.tsx:490`

```tsx
const popover = screen.getByText("Formula").closest("[class*='bg-popover']");
expect(popover).toHaveClass('bg-popover');
```

JSDOM does not process Tailwind's generated CSS. `toHaveClass('bg-popover')` only confirms the Tailwind utility class string is present on the element — it says nothing about whether `--color-popover` is defined or resolves to an opaque colour. A test that removed the token from `theme.css` entirely would still pass this assertion, because `bg-popover` is hardcoded in `popover.tsx` regardless of whether the CSS variable exists.

The test is correct as a smoke test that the component wiring hasn't changed (the class is still applied), but the Completion Notes' claim "verifies theme token contract" is overstated. The token contract (non-transparent value) is not actually testable in JSDOM.
