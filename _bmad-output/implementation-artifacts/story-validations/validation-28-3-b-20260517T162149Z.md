### 3. No Error Handling for Corrupted Population Scenarios

**Impact:** MEDIUM - Could cause cryptic runtime errors or data corruption
**Source:** AC#1, AC#3, Task 1.2-1.5

**Problem:**
The story specifies behavior for "column exists" (set_column path) and "column missing" (append_column path), but **does NOT specify behavior for corrupted scenarios**:

1. **Type mismatch:** incumbent column exists but is `pa.utf8()` instead of `pa.dictionary()`
2. **Encoding mismatch:** incumbent column is `pa.dictionary(pa.int8(), ...)` instead of `pa.dictionary(pa.int32(), ...)`
3. **Corrupted dictionary:** dictionary indices are out of bounds or null
4. **Wrong length:** incumbent column has different row count than population table

**Current implementation plan will fail with:**
- `pyarrow.lib.ArrowInvalid: Cannot append Array with different type`
- `pyarrow.lib.ArrowInvalid: Column length mismatch`
- No clear error message about what went wrong or how to fix

**Recommended Fix:**
Add to Task 1.4 (after existing validation logic):
```python
# Type validation: if column exists, must be dictionary-encoded string
if incumbent_col_name in table.column_names:
    incumbent_col = table.column(incumbent_col_name)
    if not isinstance(incumbent_col.type, pa.DictionaryType):
        raise DiscreteChoiceError(
            f"Incumbent column '{incumbent_col_name}' has wrong type: "
            f"{incumbent_col.type}. Expected pa.dictionary() for efficiency."
        )
    # Validate index type is int32 (not int8, int16, uint32)
    if incumbent_col.type.index_type != pa.int32():
        raise DiscreteChoiceError(
            f"Incumbent column '{incumbent_col_name}' has wrong dictionary index type: "
            f"{incumbent_col.type.index_type}. Expected pa.int32()."
        )
```

Add acceptance criterion: "Given a population with incumbent_heating column of plain string type (not dictionary), when writeback executes, then DiscreteChoiceError is raised with clear message about required type."
