### 2. Missing Data Source - No API Integration Specified

**Impact:** BLOCKING - Template.parameterGroups is a string array (group names only), not the parameter IDs needed for scaffolding. The story assumes parameter schemas are available but doesn't specify how to get them.

**Source:** `frontend/src/data/mock-data.ts:19`; `frontend/src/api/types.ts:113-126`; Story Implementation Strategy line 145

**Problem:**
```tsx
// Template interface has ONLY group names:

  parameterGroups: string[];  // ["Tax Rates", "Thresholds"] - NO IDs
}

// But scaffolding needs parameter IDs:
const editableParameterGroups = Array.from(groupsMap.entries()).map(
  ([name, parameterIds], idx) => ({
    id: `group-${idx}`,
    name,
    parameterIds,  // ❌ Where do these IDs come from?
  })
);
```

The only source of parameter IDs is `getTemplate(templateId)` API which returns `TemplateDetailResponse` with `default_policy`. This requires an async API call in `addTemplateInstance`.

**Recommended Fix:**
Update the implementation strategy to use `getTemplate` API:
1. Make `addTemplateInstance` async
2. Call `await getTemplate(templateId)` to fetch `TemplateDetailResponse`
3. Extract parameter IDs from `detail.default_policy` keys
4. Use the existing `mapTemplateParameters` function from `useApi.ts` to get structured parameter data
5. Build `editableParameterGroups` from the mapped parameters' `group` field

### 3. Template.parameterGroups Structure Mismatch

**Impact:** BLOCKING - The story's scaffolding code assumes `schema.group` maps to group names, but Template's `parameterGroups` is just a list of names without a reference to which parameters belong to each group.

**Source:** Story Implementation Strategy line 145-156; `mock-data.ts:99-179`

**Problem:**
```tsx
// Implementation strategy shows:
for (const schema of schemas) {
  const groupName = schema.group || "Other";
  // ❌ This assumes schemas have a 'group' field
  
  // But where do 'schemas' come from?
  // Template.parameterGroups is just: ["Tax Rates", "Thresholds"]
  // There's no mapping from parameter → group in Template
}
```

The `Parameter.group` field only exists on data returned by `mapTemplateParameters`, which requires calling `getTemplate` API. This circular dependency is not documented.

**Recommended Fix:**
Document the data flow clearly:
1. Template → `getTemplate(id)` → `TemplateDetailResponse.default_policy`
2. `default_policy` + `parameter_groups` → `mapTemplateParameters()` → `Parameter[]` (with group field)
3. `Parameter[].group` → group by group name → `EditableParameterGroup[]`
