### 1. Specify the unified hook INPUT parameter interface

**Benefit:** Prevents the developer from spending time designing a critical API that determines whether the unified hook is actually usable.
**Source:** Story Dev Notes "Hook Consolidation Pattern" section

**Current Gap:**
The story provides detailed TypeScript interfaces for the three RETURN types (`SaveDialogState`, `LoadDialogState`, `CloneDialogState`) but leaves the INPUT parameter interface as `// ... params`, completely unspecified. The three hooks have radically different parameter shapes that cannot be inferred without reading all three source files.

**Suggested Addition:**
```typescript
// INPUT discriminated union (mirrors output):
type PortfolioDialogParams =
  | {
      mode: "save";
      templates: Template[];
      composition: CompositionEntry[];
      resolutionStrategy: string;
      conflicts: PortfolioConflict[];
      loadedPortfolioRef: { current: string | null };
      setActivePortfolioName: (name: string | null) => void;
      updateScenarioPortfolioName: (name: string | null) => void;
      setSelectedPortfolioName: (name: string | null) => void;
      refetchPortfolios: () => Promise<void>;
      onSavedSuccessfully?: () => void;
      categories?: Category[] | null;
    }
  | {
      mode: "load";
      templates: Template[];
      activeScenarioPortfolioName: string | null | undefined;
      compositionLength: number;
      validStrategies: readonly string[];
      defaultResolutionStrategy: string;
      loadedPortfolioRef: { current: string | null };
      setComposition: (composition: CompositionEntry[]) => void;
      setResolutionStrategy: (strategy: string) => void;
      setActivePortfolioName: (name: string | null) => void;
      updateScenarioPortfolioName: (name: string | null) => void;
      setSelectedPortfolioName: (name: string | null) => void;
      setInstanceCounter?: (value: number) => void;
      onLoadedSuccessfully?: () => void;
    }
  | {
      mode: "clone";
      portfolios: PortfolioListItem[];
      refetchPortfolios: () => Promise<void>;
    };

// PoliciesStageScreen call pattern (three separate calls, NOT conditional):
const saveState = usePortfolioDialog({ mode: "save", templates, composition, ... });
const loadState = usePortfolioDialog({ mode: "load", templates, activeScenarioPortfolioName, ... });
const cloneState = usePortfolioDialog({ mode: "clone", portfolios, refetchPortfolios });
```

Note: Calling the hook three times (once per mode) is correct React pattern. Do NOT call conditionally based on a runtime mode value — that would violate Rules of Hooks.

### 2. Backward-compatibility re-export must be a wrapper function, not a re-export alias

**Benefit:** Prevents the existing `usePortfolioSaveDialog.nameFreeze.test.ts` from breaking immediately on refactor.
**Source:** Story Dev Notes "Backward Compatibility Strategy"

**Current Gap:**
The story specifies:
```typescript
// usePortfolioSaveDialog.ts (after refactoring)
export { usePortfolioDialog as usePortfolioSaveDialog } from './usePortfolioDialog';
```
This is a re-export *alias* — calling `usePortfolioSaveDialog(params)` would still require `params.mode === "save"` if the signature is discriminated-union-based. Existing tests call `usePortfolioSaveDialog({ templates, composition, ... })` without `mode`. The alias would break them.

**Suggested Addition:**
Replace re-export alias with wrapper function:
```typescript
// usePortfolioSaveDialog.ts (after refactoring) — backward compat wrapper
import { usePortfolioDialog } from './usePortfolioDialog';
import type { Template } from '@/data/mock-data';
// ... other types

export type UsePortfolioSaveDialogParams = Omit<SaveDialogParams, "mode">;

/** @deprecated Use `usePortfolioDialog({ mode: "save", ... })` directly. */
export function usePortfolioSaveDialog(params: UsePortfolioSaveDialogParams) {
  return usePortfolioDialog({ mode: "save", ...params });
}
```
Apply same pattern for `usePortfolioLoadDialog` and `usePortfolioCloneDialog`.
