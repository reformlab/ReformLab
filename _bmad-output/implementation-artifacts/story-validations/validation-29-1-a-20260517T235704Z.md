### 3. Architectural Boundary Violation

**Impact:** CRITICAL - Violates core architectural principle

**Source:** Project Structure Notes, architecture.md

**Problem:**
Story proposes creating `src/reformlab/computation/openfisca_extension/` with custom Variable classes. This directly violates the "Adapter isolation is absolute" principle from architecture.md and CLAUDE.md:

> "Adapter isolation is absolute — Only modules under `src/reformlab/computation/` may import OpenFisca."

The extension modules would need to `from openfisca_core import Variable` which breaks the boundary. The adapter exists precisely to hide OpenFisca details from the rest of the codebase.

**Recommended Fix:**
Implement custom variable logic in the adapter layer, not as OpenFisca extensions. The adapter can:
1. Compute custom variables from existing OpenFisca outputs
2. Add them to `ComputationResult.output_fields` before normalization
3. Keep all OpenFisca imports isolated to `openfisca_api_adapter.py`
