### 1. Missing Draft Version Field (Schema Migration Risk)

**Impact:** When CompositionEntry schema changes in future stories, old saved drafts will fail to load with no migration path, causing data loss for users.

**Source:** Data Structures section, line 125-132

**Problem:**
```tsx
interface CompositionDraft {
  composition: CompositionEntry[];
  resolutionStrategy: string;
  instanceCounter: number;
  savedPortfolioName: string | null;
  timestamp: number;  // ← Also problematic (see issue #7)
}
```
No version field means when `CompositionEntry` adds new fields (like `editableParameterGroups` in Story 27.4), old drafts become incompatible.

**Recommended Fix:**
Add a version field to the schema:
```tsx
interface CompositionDraft {
  version: 1;  // Increment when schema changes
  composition: CompositionEntry[];
  resolutionStrategy: string;
  instanceCounter: number;
  savedPortfolioName: string | null;
  timestamp: number;
}
```
Update `loadCompositionDraft()` to check version and migrate or discard old drafts:
```tsx
export function loadCompositionDraft(): CompositionDraft | null {
  try {
    const raw = localStorage.getItem(COMPOSITION_DRAFT_KEY);
    if (!raw) return null;
    const parsed = JSON.parse(raw) as CompositionDraft;
    if (parsed.version !== 1) return null; // Discard incompatible drafts
    return parsed;
  } catch {
    return null;
  }
}
```

### 3. Race Condition in Save Effect (Data Corruption Risk)

**Impact:** Draft may be saved with stale `instanceCounterRef.current` value, causing duplicate instanceId conflicts on restore.

**Source:** Tasks 2.3, 2.4, lines 35-38

**Problem:**
Task 2.3 says "Include `instanceCounterRef.current` in the draft payload" but Task 2.4 says "Debounce the save effect by 500ms" with dependencies `[composition, resolutionStrategy]`.

The effect doesn't depend on `instanceCounterRef.current`, so rapid adds could trigger save before counter updates:
```tsx
useEffect(() => {
  // Debounced save
  saveCompositionDraft({
    ...composition,
    instanceCounter: instanceCounterRef.current, // Stale value!
  });
}, [composition, resolutionStrategy]); // Missing instanceCounterRef dependency
```

**Recommended Fix:**
Specify that the save effect must capture `instanceCounterRef.current` atomically within the debounced callback, not in the dependency array:
```tsx
useEffect(() => {
  const timer = setTimeout(() => {
    saveCompositionDraft({
      composition,
      resolutionStrategy,
      instanceCounter: instanceCounterRef.current, // Capture at save time
      // ...
    });
  }, 500);
  return () => clearTimeout(timer);
}, [composition, resolutionStrategy]);
```
Add explicit note: "instanceCounterRef.current is captured inside the debounced callback, not as a dependency, to avoid excessive re-renders."

### 7. Timestamp Type Contradiction (Schema Confusion)

**Impact:** Developers won't know whether to store Unix epoch number or ISO string, causing parse errors.

**Source:** Data Structures section, line 130

**Problem:**
```tsx
interface CompositionDraft {

```
The type is `number` but the comment says "ISO timestamp". ISO timestamps are strings (e.g., "2026-04-30T12:34:56Z").

**Recommended Fix:**
Pick one and be consistent:
```tsx

// OR

```
Update all references to match the chosen format.
