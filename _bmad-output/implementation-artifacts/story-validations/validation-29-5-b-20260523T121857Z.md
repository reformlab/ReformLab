## ✨ Optimizations (Nice to Have)

### 1. Imprecise Permissive Promotion Description

**Value:** Prevents a developer from writing incorrect type assertions for null-filled columns

**Suggestion:**

The Dev Notes section states:

> **Missing columns**: filled with a null-typed column (all values `null`) — column type is `null` for the missing rows

The phrasing "column type is `null` for the missing rows" is ambiguous. The actual behavior is: the **column retains its type** from the year that has the column (e.g., `float64`); only the **values** for the missing rows are null. Replace with:

> **Missing columns**: filled with null values for the rows that lack the column — the column type is retained from the schema of the year(s) that do have the column (e.g., a `float64` column absent in one year will appear as `float64` with null values, not as a `null`-typed column).

This distinction matters if a developer writes type assertions like `pa.types.is_null(...)` for the null-fill scenario (which would be wrong).
