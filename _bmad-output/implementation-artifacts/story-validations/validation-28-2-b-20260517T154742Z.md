```markdown
### Performance Characteristics of Dictionary Encoding

**Why dictionary encoding:**
- Memory: O(unique_values) instead of O(num_rows) for string storage
- Filtering: O(1) categorical equality checks (no string comparisons)
- Grouping: Fast group-by operations on categorical data

**Expected improvement:**
For 100k households with ~10 unique incumbent values:
- String storage: ~800KB (assuming 8 bytes per string)
- Dictionary encoding: ~1.2MB total (dict: ~80B + indices: ~1.2MB)
- But faster filtering: 10x speedup for `incumbent == "gas_boiler"` operations

**Tradeoffs:**
- Slightly higher memory for low-cardinality columns
- Extra encoding step during migration
- Decoding needed for certain operations (PyArrow handles transparently)
```

## ✨ Optimizations (Nice to Have)

Performance hints, development tips, and additional context for complex scenarios.

### 1. Suggest Using PyArrow's compute module for Value Counts

**Value:** More efficient than manual dictionary extraction  
**Suggestion:**

Instead of:
```python
if isinstance(incumbent_col.type, pa.DictionaryType):
    unique_values = set(incumbent_col.dictionary.to_pylist())
```

Consider using:
```python
import pyarrow.compute as pc

# Get value counts for validation
value_counts = pc.value_counts(incumbent_col)
unique_values = set(value_counts['values'].to_pylist())
```

This handles both dictionary and plain string columns uniformly and provides counts for error messages.

### 2. Recommend Caching Validation Results

**Value:** Avoid redundant validation in multi-year scenarios  
**Suggestion:**

In multi-year scenarios, validation runs every year but population incumbents don't change during simulation. Consider caching validation results:

```python
# In DiscreteChoiceStep.execute()
validation_cache_key = f"population_validation_{id(population)}"
```
