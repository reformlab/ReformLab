## Issues Dismissed

- **Portfolio rename/delete orphaning**: savedPortfolioName could reference deleted portfolio | **Raised by**: Validator A | **Dismissal Reason**: Out of scope for this story. Draft restoration correctly sets `activePortfolioName = null`. Portfolio validation during load is a separate concern handled by existing portfolio management. The "orphan reference" is expected behavior - it indicates "unsaved changes to [what was previously named X]" which is accurate.
- **Cross-scenario contamination**: Global localStorage key shared across scenarios | **Raised by**: Validator B | **Dismissal Reason**: Per project pattern (useScenarioPersistence), localStorage keys are global. This is intentional - the draft represents the user's most recent composition work regardless of scenario. The design allows continuing work across scenarios, which is a feature not a bug.
- **Restore precedence ambiguity**: Conflict between draft restore and scenario autoload | **Raised by**: Validator B | **Dismissal Reason**: AC-2 already specifies restore only when "composition is empty". If scenario autoload populated composition, draft won't restore. The precedence rule exists: existing composition takes priority over draft.
- **Namespace draft key by scenarioId**: Would prevent cross-scenario contamination | **Raised by**: Validator B | **Dismissal Reason**: Changes feature intent. User's most recent draft should be accessible regardless of scenario context. Namespace isolation is a different design choice requiring broader discussion.
