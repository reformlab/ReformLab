### 2. Parameter Schemas Not Wired — AC-5 Has No Data Source for Units

**Impact:** `extractPrimaryParameterValue(entry, schemas)` and `formatParameterForName(value, unit)` require `unit` from `Parameter.unit`. This field is not available in `CompositionEntry` and is not stored in `PoliciesStageScreen` state. Without units, the formatter cannot produce "44eur" or "20pct" — it can at best produce "44" or "0.2".

**Source:** Tasks 2, 3, 4; `PoliciesStageScreen.tsx:addTemplateInstance`; `PolicyCard.tsx:140`

**Problem:**
The story references `schemas: Parameter[]` throughout Task 2 but no task stores them. The flow is:
1. `addTemplateInstance()` calls `getTemplate()` → gets `detail.parameters: Parameter[]`
2. Only `editableParameterGroups` is extracted and stored in `CompositionEntry`
3. `Parameter[]` (with `unit`, `baseline`) is discarded
4. `usePortfolioSaveDialog` has no access to schemas
5. `generatePortfolioSuggestion` has no access to schemas

**Recommended Fix (Option A — preferred):** Add Subtask 1.x: store `Record<string, Parameter[]>` in PoliciesStageScreen state (update in `addTemplateInstance`); add `schemas?: Record<string, Parameter[]>` to `UsePortfolioSaveDialogParams`; thread to `generatePortfolioSuggestion`.

**Recommended Fix (Option B — minimal scope):** Redesign `extractPrimaryParameterValue` to return `{paramId, value}` without unit. Add heuristic in `formatParameterForName`: if `paramId` contains "rate" AND value is between 0 and 1, treat as decimal percentage (`Math.round(value * 100) + "pct"`); if value ≥ 10, treat as currency integer (`Math.round(value) + "eur"`). Document this explicitly.
