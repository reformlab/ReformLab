### 2. Undiscovered 4th statusVariant in ExecutionMatrix.tsx — Type-Incompatible

**Impact:** Consolidation that doesn't handle ExecutionMatrix would silently produce wrong badge colors for that component.
**Source:** `frontend/src/components/comparison/ExecutionMatrix.tsx:43`

**Problem:**
The story identifies 3 statusVariant duplicates. There are actually 4. The one in `ExecutionMatrix.tsx` uses **uppercase** `ExecutionStatus` enum values:
```typescript
function statusVariant(status: ExecutionStatus): "success" | "destructive" | "warning" | "default" {
  switch (status) {
    case "COMPLETED": return "success";
    case "FAILED":    return "destructive";
    // ...
  }
}
```
The proposed consolidated helper takes lowercase `string` values. Migrating ExecutionMatrix to use the consolidated helper without handling case normalization would break status display for the entire execution matrix view.

**Recommended Fix:**
Add ExecutionMatrix.tsx to the statusVariant migration list. Either: (a) add uppercase→lowercase normalization in the consolidated helper, or (b) keep ExecutionMatrix's variant separate with a comment explaining the type difference.

### 4. policyLabel Helper Type Signature Incompatible with Actual API Types

**Impact:** TypeScript type errors at every call site when migrating.
**Source:** Proposed spec vs `ResultListItem` and `ResultDetailResponse` types

**Problem:**
The proposed helper:
```typescript
policyLabel(run: { scenarioName?: string; portfolioName?: string }): string
```
Uses camelCase. The actual `ResultListItem` type (used in `ResultsListPanel`) has `portfolio_name`, `template_name`, and `run_kind` (all snake_case). `ResultDetailResponse` (used in `ResultDetailView`) has the same snake_case pattern.

Additionally, the current `ResultsListPanel.policyLabel` returns `"Scenario"` for non-portfolio runs (`run_kind !== "portfolio"`). The proposed consolidation always returns `"Portfolio run"` which removes this distinction.

**Recommended Fix:**
Change the helper signature to match actual API types:
```typescript
policyLabel(run: { portfolio_name?: string | null; template_name?: string | null; run_kind?: string }): string
// return run.portfolio_name || run.template_name || (run.run_kind === "portfolio" ? "Portfolio run" : "Scenario run")
```
