## Challenges and Growth Areas

### AC-5 Production Gap in Story 27.9 (Policy Set Auto-Name)
**Issue:** Parameter enrichment feature (AC-5) completely non-functional in production due to missing `parameterSchemas` wiring.

**Root Cause:** Implementation added helper functions but didn't integrate API calls to fetch parameter schemas from templates.

**Impact:** Users don't get parameter-enriched names (e.g., "tax-carbon-emissions-44eur") - they only get type-category names.

**Recommended Action:** Create dedicated story to wire `getTemplate()` API calls through to `usePortfolioSaveDialog`, implement caching strategy, and complete AC-5.

### AC-9 Incomplete Migration in Story 27.10 (Formatters)
**Issue:** Story claimed all `.toLocaleString()` calls migrated, but 38 instances remain in 22 files (only ~15% complete).

**Root Cause:** Scope misestimation - task enumerated 26 files but implementation only covered 7 components.

**Impact:** Inconsistent number/currency/date formatting across application. Future formatter changes require touching many more files.

**Status:** Deferred as AI Review action item. Requires dedicated PR to migrate remaining files.

### Stage-Touch Lifecycle Complexity (Story 27.6)
**Issue:** Initial implementation didn't write `stageTouched` markers when users interacted with stages, causing nav-rail to show incorrect state.

**Root Cause:** Task explicitly stated "Mark a stage touched: true when user explicitly visits and acts on it" but implementation only defined the data structure.

**Resolution:** Code review synthesis identified gap; fixes applied via `updateScenarioField()` and `startRun()` hooks.

**Lesson Learned:** Explicit state-machine requirements need end-to-end implementation verification, not just data structure definition.

### URL Hash Migration Timing (Story 27.8)
**Issue:** Initial implementation placed legacy hash migration AFTER `isValidSubView()` check, so `"population-explorer"` passed validation without being migrated to `"inspect"`.

**Root Cause:** Ordering logic error in `onHashChange` handler.

**Resolution:** Code review synthesis identified bug; reordered migration check before validation.

### Complex State Management in AppContext
Multiple stories (27.5, 27.6, 27.13) modified `AppContext.tsx`, creating interaction risks:

**State Added:**
- `stageTouched: Partial<Record<StageKey, boolean>>`
- `isDefaultPopulationSelection` ref
- `lastRestoreTimestamp` ref
- `seenScenarioIdsInAutoName` ref

**Challenge:** 6 refs and complex effects increase risk of stale closures, race conditions.

**Evidence:** Story 27.13 required fixes for stale closure and flag leaks.

**Lesson:** Centralized state management complexity is growing; consider state machine extraction for Epic 28.

## Key Insights

1. **AI Review Synthesis Adds Value:** Consistently caught critical bugs (stale closures, lifecycle gaps, incomplete migrations) that slipped through initial implementation. Worth the additional review cycle time.

2. **Documentation-Only Stories Need Same Rigor:** Story 27.15 (UX spec amendments) received code review synthesis that found 6 documentation issues and applied fixes. Specification accuracy matters as much as code.

3. **Migration Testing is Critical:** Every breaking-change story (27.6, 27.8, 27.13) included migration tests that caught regressions. Pattern: test legacy → current → migrated states.

4. **Formatters Consolidation Underestimated:** Story 27.10's 15% completion reveals scope creep pattern. What seemed like "find and replace" actually required careful locale exception identification and extensive file-by-file review.

5. **Backward Compatibility Tax:** All migration logic adds maintenance burden. Story 27.13's 5 ref migrations, Story 27.8's hash migrations - these accumulate. Consider deprecation timelines.

6. **Component Extraction Reduces Duplication:** Story 27.4's PolicyCard extraction (from 780 to 280 lines in PortfolioCompositionPanel) demonstrates clear value. Pattern repeated in Story 27.10 (formatters), Story 27.11 (hooks).

7. **Auto-Save Requires Careful Guard Logic:** Story 27.5's draft auto-save needed `isProgrammaticLoadRef` to prevent auto-save during portfolio load/draft restore. Pattern: distinguish user edits from programmatic changes.

8. **Visual Consistency Has Hidden Complexity:** Badge variant fixes (Story 27.14) required finding 6 bypasses across 4 files. Visual inconsistencies accumulate unnoticed; systematic audits valuable.
